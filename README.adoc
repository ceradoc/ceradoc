*Coridoc has been renamed **Ceradoc*** (2026-11-25).

**Cera** (Latin: _cera_, wax — the sealing wax pressed into documents to mark
them authentic) + **Doc** (document) — the seal of interoperable document
information. Where the _cor_ (heart) is the canonical model, the _cera_ seal is
what it presses into every format: faithful, verifiable, round-trip-intact.

History: Coradoc -> Coridoc -> Ceradoc. The project lives at
link:https://github.com/ceradoc[github.com/ceradoc] and
link:https://www.ceradoc.org[www.ceradoc.org]. Gems are published as
(`ceradoc`, `ceradoc-adoc`, `ceradoc-markdown`, `ceradoc-html`, `ceradoc-docx`,
`ceradoc-mirror`); the legacy `coradoc*` and `coridoc*` gems on RubyGems.org are
frozen and will not receive further releases. Module namespace: `Ceradoc`;
CLI: `ceradoc`; environment variables: `CERADOC_*`.
====

== Purpose

Ceradoc is a hub-and-spoke document transformation library for Ruby.
It provides a canonical CoreModel that serves as the transformation hub,
enabling seamless conversions between AsciiDoc, HTML, Markdown, DOCX, and other formats.

== Features

* link:#hub-and-spoke-architecture[Hub-and-Spoke Architecture] - CoreModel as canonical representation
* link:#format-conversion[Format Conversion] - Convert between any supported formats
* link:#developer-api[Developer API] - Simple, intuitive Ruby API
* link:#cli[Command-Line Interface] - CLI for quick conversions
* link:#extensibility[Extensibility] - Add new formats with minimal code
* link:#query-api[Query API] - CSS-like selectors for document querying
* link:#validation-framework[Validation Framework] - Schema-based document validation
* link:#streaming-processor[Streaming Processor] - Process large documents efficiently
* link:#lazy-evaluation[Lazy Evaluation] - Memory-efficient lazy document processing

== Architecture

=== Hub-and-Spoke Model

Ceradoc uses a hub-and-spoke architecture where all format transformations go through a canonical CoreModel:

....
                    ┌─────────────────────────────────────┐
                    │           Source Formats            │
                    │                                     │
    ┌─────────┐     │  ┌─────────┐  ┌─────────┐  ┌──────┐ │     ┌─────────┐
    │AsciiDoc │────►│  │ ToCore  │  │  From  │  │ HTML │────►│   HTML  │
    │  .adoc  │     │  │         │  │  Core  │  │Render│ │     │  .html  │
    └─────────┘     │  │         │  │         │  │      │ │     └─────────┘
                    │  │         ▼  ▼         │  │      │ │
    ┌─────────┐     │  │      ┌─────────┐     │  │      │ │     ┌─────────┐
    │Markdown │────►│  │      │CoreModel│     │  │      │────►│Markdown │
    │   .md   │     │  │      │   Hub   │     │  │      │ │     │   .md   │
    └─────────┘     │  │      └─────────┘     │  │      │ │     └─────────┘
                    │  │                     │  │      │ │
    ┌─────────┐     │  │                     │  │      │ │     ┌─────────┐
    │  HTML   │────►│  │                     │  │      │────►│ AsciiDoc│
    │  .html  │     │  └─────────────────────┘  └──────┘ │     │  .adoc  │
    └─────────┘     │                                      │     └─────────┘
                    └──────────────────────────────────────┘
    ┌─────────┐
    │  DOCX   │────► ToCoreModel (via Uniword) ──► CoreModel Hub
    │  .docx  │
    └─────────┘
....

This architecture means:
- Adding a new format only requires two transformers (ToCoreModel, FromCoreModel)
- N formats can interoperate with just 2N transformers (not N*(N-1))
- The CoreModel provides a canonical, well-defined structure

=== CoreModel

The CoreModel (`Ceradoc::CoreModel`) is the canonical representation of documents:

[horizontal]
`StructuralElement`:: Document structure (document, section)
`Block`:: Content blocks (paragraph, code, quote)
`ListBlock`:: Lists (ordered, unordered, definition)
`InlineElement`:: Inline formatting (bold, italic, link)
`Table`:: Tables with rows and cells
`Image`:: Images with alt text

== Installation

Add this line to your application's Gemfile:

[source,ruby]
----
gem 'ceradoc'

# For DOCX support, also add:
gem 'ceradoc-docx'
gem 'uniword'        # DOCX reader
----

And then execute:

[source,bash]
----
bundle install
----

Or install it yourself as:

[source,bash]
----
gem install ceradoc
----

== Quick Start

=== Using the Developer API

[source,ruby]
----
require 'ceradoc'
require 'ceradoc/html'
require 'ceradoc/markdown'

# Convert Markdown to HTML
html = Ceradoc.convert("# Title\n\nParagraph", from: :markdown, to: :html)

# Parse to CoreModel
core = Ceradoc.parse("# Title\n\nParagraph", format: :markdown)

# Serialize to any format
markdown = Ceradoc.serialize(core, to: :markdown)
html = Ceradoc.serialize(core, to: :html)
----

=== DOCX Conversion

Convert Word documents to AsciiDoc or Markdown:

[source,ruby]
----
require 'ceradoc'
require 'ceradoc/docx'

# Convert DOCX to AsciiDoc
adoc = Ceradoc.convert("input.docx", from: :docx, to: :asciidoc)

# Convert DOCX to Markdown
md = Ceradoc.convert("input.docx", from: :docx, to: :markdown)

# Parse DOCX to CoreModel for manipulation
core = Ceradoc.parse("input.docx", format: :docx)
core.title         # => "Document Title"
core.children      # => Array of sections, paragraphs, tables, etc.

# Serialize to different formats
adoc = Ceradoc.serialize(core, to: :asciidoc)
md  = Ceradoc.serialize(core, to: :markdown)
----

=== Using the CLI

[source,bash]
----
# Convert Markdown to HTML
ceradoc convert document.md -o output.html

# Convert with auto-detection
ceradoc convert document.adoc --to html

# List supported formats
ceradoc formats

# Show version
ceradoc version
----

== Developer API

[[format-conversion]]
=== Format Conversion

The `Ceradoc.convert` method handles the complete transformation pipeline:

[source,ruby]
----
# AsciiDoc to HTML
html = Ceradoc.convert(adoc_text, from: :asciidoc, to: :html)

# Markdown to HTML
html = Ceradoc.convert(md_text, from: :markdown, to: :html)

# HTML to Markdown
md = Ceradoc.convert(html_text, from: :html, to: :markdown)

# DOCX to AsciiDoc (requires ceradoc-docx gem)
adoc = Ceradoc.convert("document.docx", from: :docx, to: :asciidoc)

# DOCX to Markdown
md = Ceradoc.convert("document.docx", from: :docx, to: :markdown)
----

[[parsing]]
=== Parsing

Parse documents to CoreModel for manipulation:

[source,ruby]
----
# Parse Markdown
core = Ceradoc.parse("# Title\n\nContent", format: :markdown)

# Access the structure
core.element_type  # => "document"
core.title         # => "Title"
core.children      # => Array of child elements
----

[[serialization]]
=== Serialization

Serialize CoreModel to any supported format:

[source,ruby]
----
# Create or modify CoreModel
core = Ceradoc::CoreModel::StructuralElement.new(
  element_type: "document",
  title: "My Document",
  children: [...]
)

# Serialize to HTML
html = Ceradoc.serialize(core, to: :html)

# Serialize to Markdown
md = Ceradoc.serialize(core, to: :markdown)
----

=== Transform Models

Transform between format-specific models:

[source,ruby]
----
# Parse Markdown to its native model
md_doc = Ceradoc::Markdown.parse("# Title\n\nContent")

# Transform to CoreModel
core = Ceradoc.to_core(md_doc)

# Transform back to Markdown model
md_doc2 = Ceradoc::Markdown.from_core_model(core)
----

=== Metanorma semantic output (optional)

The optional Metanorma integration builds a native
`Metanorma::Standoc::Document::Root` directly from the shared CoreModel.
It accepts AsciiDoc and Markdown through their normal frontends:

[source,ruby]
----
require 'ceradoc/metanorma'

root = Ceradoc::Metanorma::Builder.parse(source, format: :asciidoc)
root = Ceradoc::Metanorma::Builder.parse(markdown, format: :markdown)
root = Ceradoc::Metanorma::Builder.build(core_document)

# Explicit ISO output uses actual ISO root, metadata and section classes.
require 'metanorma/iso/document'
iso_root = Ceradoc::Metanorma::Builder.parse(source,
  root_class: Metanorma::Iso::Document::Root)
xml = root.to_xml
----

ISO output classifies a top-level heading named `Scope` as the native scope
clause. A nested heading with that name remains an ordinary clause.

In Markdown, an authored block ID uses a following Kramdown IAL such as
`{: #method}`. Internal links such as `[label](#method)` produce semantic cross
references; `[](#method)` leaves the display label to the downstream presenter.
Other block attributes fail explicitly when the native model cannot represent them.

Install the optional SDK dependencies through
`gemfiles/metanorma.gemfile`. This separate bundle pins the accepted SDK
revision until its model changes are released; generic Ceradoc users do not
load or install the SDK.

The builder supports sections, mixed inline content, cross references,
lists, tables, figures, source code, notes, formulas and bibliography entries.
It preserves authored IDs and assigns deterministic generated IDs without
mutating the input CoreModel. Document metadata must be supplied by the source;
the builder does not invent publication defaults. This is a bounded semantic
producer, rather than full Standoc converter parity: unsupported nodes,
raw passthrough, includes, custom attributes and unknown metadata raise
`Ceradoc::Metanorma::UnsupportedNode`. Schema validation and rendering remain
separate steps.

Run the explicit integration checks with:

[source,sh]
----
BUNDLE_GEMFILE=gemfiles/metanorma.gemfile bundle install
CERADOC_METANORMA_TEST=1 BUNDLE_GEMFILE=gemfiles/metanorma.gemfile bundle exec rspec --options /dev/null ceradoc/spec/ceradoc/metanorma/builder_spec.rb
----

== CLI

The `ceradoc` command-line tool provides quick conversions:

[source,bash]
----
# Basic conversion
ceradoc convert input.md -o output.html

# Specify formats explicitly
ceradoc convert input.md --from markdown --to html

# Convert DOCX to AsciiDoc (requires ceradoc-docx gem)
ceradoc convert document.docx -o output.adoc

# Convert DOCX to Markdown
ceradoc convert document.docx -o output.md

# Use different HTML themes
ceradoc convert input.md -o output.html --theme modern

# Verbose output
ceradoc convert input.md -o output.html --verbose

# Show supported formats
ceradoc formats
----

=== CLI Options

[horizontal]
`--to, -t FORMAT`:: Target format (html, md, adoc)
`--from, -f FORMAT`:: Source format (auto-detected from extension)
`--output, -o FILE`:: Output file (default: stdout)
`--theme THEME`:: HTML theme (classic, modern)
`--verbose`:: Enable verbose output

== Extensibility

[[extensibility]]
=== Adding a New Format

To add a new format, create a gem with:

1. **Format module** with parse/serialize methods
2. **ToCoreModel transformer** - converts native model to CoreModel
3. **FromCoreModel transformer** - converts CoreModel to native model
4. **Register with Ceradoc**

[source,ruby]
----
# lib/ceradoc/my_format.rb
module Ceradoc
  module MyFormat
    # Parse input to native model
    def self.parse(content)
      # ...
    end

    # Parse directly to CoreModel
    def self.parse_to_core(content)
      Transform::ToCoreModel.transform(parse(content))
    end

    # Transform native model to CoreModel
    def self.to_core(model)
      Transform::ToCoreModel.transform(model)
    end

    # Transform CoreModel to native model
    def self.from_core(core)
      Transform::FromCoreModel.transform(core)
    end

    # Serialize CoreModel to output
    def self.serialize(core, **options)
      model = from_core(core)
      serialize_native(model)
    end
  end
end

# Register the format
Ceradoc.register_format(:my_format, Ceradoc::MyFormat,
                        extensions: ['.myf', '.myformat'])
----

=== Plugin Lifecycle Hooks

Hook into the transformation pipeline:

[source,ruby]
----
# Register hooks via options
Ceradoc.convert(text, from: :markdown, to: :html,
  before_parse: ->(content) { content.upcase },
  after_transform: ->(core) { process(core) }
)
----

== CoreModel Reference

=== Structural Elements

[source,ruby]
----
# Document
doc = Ceradoc::CoreModel::StructuralElement.new(
  element_type: "document",
  title: "My Document",
  children: [...]
)

# Section
section = Ceradoc::CoreModel::StructuralElement.new(
  element_type: "section",
  level: 1,
  title: "Section Title",
  children: [...]
)
----

=== Block Elements

[source,ruby]
----
# Paragraph
para = Ceradoc::CoreModel::Block.new(
  element_type: "paragraph",
  content: "Paragraph text"
)

# Code block
code = Ceradoc::CoreModel::Block.new(
  element_type: "block",
  delimiter_type: "----",
  content: "def hello; puts 'world'; end",
  language: "ruby"
)
----

=== Lists

[source,ruby]
----
# Unordered list
list = Ceradoc::CoreModel::ListBlock.new(
  marker_type: "unordered",
  items: [
    Ceradoc::CoreModel::ListItem.new(content: "Item 1", marker: "*"),
    Ceradoc::CoreModel::ListItem.new(content: "Item 2", marker: "*"),
  ]
)

# Definition list
def_list = Ceradoc::CoreModel::DefinitionList.new(
  items: [
    Ceradoc::CoreModel::DefinitionItem.new(
      term: "API",
      definitions: ["Application Programming Interface"]
    ),
  ]
)
----

=== Inline Elements

[source,ruby]
----
# Bold
bold = Ceradoc::CoreModel::InlineElement.new(
  format_type: "bold",
  content: "bold text"
)

# Link
link = Ceradoc::CoreModel::InlineElement.new(
  format_type: "link",
  target: "https://example.com",
  content: "Example"
)

# STEM formula
stem = Ceradoc::CoreModel::InlineElement.new(
  format_type: "stem",
  content: "E = mc^2",
  stem_type: "stem"
)
----

[horizontal]
`bold`:: Bold text
`italic`:: Italic/emphasized text
`monospace`:: Code/monospace text
`link`:: Hyperlinks
`xref`:: Cross-references
`stem`:: STEM formulas (mathematical notation)
`footnote`:: Footnotes
`term`:: Term references (glossary terms)
`superscript`:: Superscript text
`subscript`:: Subscript text

=== Query API

Query documents using CSS-like selectors:

[source,ruby]
----
# Parse document
doc = Ceradoc.parse(adoc_text, format: :asciidoc)

# Find all sections
sections = doc.query('section')

# Find level-2 sections
doc.query('section.level-2').each do |section|
  puts section.title
end

# Find paragraphs with specific role
examples = doc.query('[role=example]')

# Complex selectors with pseudo-classes
doc.query('section > paragraph:first-child')

# Query within a specific element
doc.query_within(section, 'paragraph')

# Chain queries
doc.query('section').filter('.important').first
----

==== Selector Syntax

[horizontal]
`element`:: Element type (section, paragraph, table)
`#id`:: ID selector
`.class`:: Class/role selector
`[attr=value]`:: Attribute selector
`:first-child`:: Pseudo-class selectors
`>`:: Child combinator
(space):: Descendant combinator

=== Validation Framework

Validate documents against schemas:

[source,ruby]
----
# Define a validation schema
schema = Ceradoc::Validation::Schema.define do
  required :title, type: String, min_length: 1
  required :sections, type: Array, min_count: 1
  optional :author, type: String

  rule :check_references do |doc|
    refs = doc.query('xref')
    missing = refs.reject { |r| doc.resolve_reference(r) }
    missing.map { |r| "Unresolved reference: #{r.target}" }
  end
end

# Validate a document
result = schema.validate(document)

if result.valid?
  puts "Document is valid"
else
  result.errors.each { |e| puts "#{e.path}: #{e.message}" }
end
----

==== Built-in Validation Rules

[horizontal]
`required`:: Field must be present
`type`:: Field must be specific type
`min_length`/`max_length`:: String/collection length bounds
`min_count`/`max_count`:: Collection count bounds
`format`:: Match against regex pattern
`rule`:: Custom validation block

=== Streaming Processor

Process large documents without loading everything into memory:

[source,ruby]
----
# Stream parse large file
Ceradoc::Streaming.parse_large_file("large.adoc", format: :asciidoc,
                                    chunk_size: 100) do |chunk|
  chunk.each { |element| process_element(element) }
end

# Transform in chunks
results = Ceradoc::Streaming.transform_in_chunks(elements, chunk_size: 50) do |chunk|
  chunk.map { |el| transform_element(el) }
end

# Incremental serialization
File.open("output.html", "w") do |file|
  Ceradoc::Streaming.serialize_incremental(document, format: :html) do |chunk|
    file.write(chunk)
  end
end

# Process with memory constraints
progress = Ceradoc::Streaming.process_with_memory_limit(
  "input.adoc", "output.html",
  format: :asciidoc, output_format: :html,
  max_memory: 50 * 1024 * 1024  # 50MB
)
puts progress.to_s  # "100 processed (100.0%) at 10.0/sec ~0.5min remaining"
----

==== Streaming Features

[horizontal]
`ChunkProcessor`:: Batch operations with configurable chunk size
`Progress`:: Track progress, rate, estimated time remaining
`MemoryMonitor`:: Monitor memory usage during processing
`StreamReader`/`StreamWriter`:: File I/O streaming

=== Lazy Evaluation

Memory-efficient processing using lazy enumerators and on-demand evaluation:

[source,ruby]
----
# Wrap document for lazy iteration
wrapper = Ceradoc::Lazy.wrap(document)
wrapper.each_section do |section|
  process_section(section)  # Processed on-demand
end

# Lazy transformation pipeline
result = Ceradoc::Lazy.transform(sections) do |p|
  p.map { |s| transform_section(s) }
   .select { |s| s.visible? }
   .take(10)
end.to_a  # Only evaluates when to_a is called

# Process in batches
wrapper.each_batch(10) do |batch|
  batch.each { |section| process(section) }
end

# Lazy reference resolution
resolver = Ceradoc::Lazy.resolver(document, loader: ->(ref, _) {
  load_include_file(ref)
})
content = resolver.resolve("include::chapter1.adoc[]")
----

==== Lazy Evaluation Features

[horizontal]
`DocumentWrapper`:: Lazy iteration over document sections
`TransformationPipeline`:: Chain lazy transformations without evaluation
`ReferenceResolver`:: On-demand loading of includes/references
`ChunkProcessor`:: Process large content in memory-safe chunks
